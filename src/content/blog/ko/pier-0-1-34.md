Pier 0.1.34(2026-08-30)에서는 후보 버전을 미리 받을지 고를 수 있습니다. 창 이동, 명령줄로 파일 열기, 커밋 확인도 보탰습니다.

## 후보 버전을 미리 받을 수 있습니다

설정 → 업데이트에 「후보 버전 받기」가 생겼고, 기본값은 꺼짐입니다. 켜면 정식 버전 전에 후보가 오고, 정식이 나오면 자동으로 바뀝니다. 꺼 두면 정식만 받습니다.

## 패널을 다른 창으로 옮길 수 있습니다

탭을 오른쪽 클릭합니다. 창이 두 개면 다른 쪽으로 바로 옮기고, 더 있으면 메뉴에서 대상을 고릅니다.

## 명령줄로 디렉터리와 파일을 엽니다

`pier .` 또는 경로 줄임말은 이미 연 프로젝트로 가거나, 편집기에서 파일을 엽니다. 경로 뒤에 `:줄` 또는 `:줄:열`을 붙일 수 있습니다.

## Git 변경 페이지에서 커밋을 확인합니다

커밋 명령과 커밋하지 않은 변경 페이지는 같은 입구입니다. 확인 카드가 나온 뒤 커밋합니다. 이번에 체크한 항목이 다음 기본값을 몰래 바꾸지 않습니다.

## 더 많은 프로젝트 파일을 알아봅니다

Dart, CMake, Python, Go, Maven, Gradle 같은 프로젝트 파일을 알아보고 맞는 작업을 제공합니다. Dart는 워크스페이스의 FVM을 우선합니다.

## 그 밖의 개선

- 새로 연 관련 패널은 지금 탭 오른쪽에 놓입니다.
- 이미 프로젝트 기억을 켠 저장소는 저장소 안의 파일을 바꿀 필요가 없고, 시작할 때 설명을 명령줄에 넘깁니다.
- 창 제목에 폴더 이름이 겹치지 않고, 오른쪽에는 다른 브랜치나 지금 파일만 나옵니다.
- 명령줄에 새 버전이 있는지는 해당 설치 출처로 판단하고, 오래된 로컬 인덱스를 최신으로 보지 않습니다.
- Kimi Code만 업데이트합니다. PATH의 옛 Python `kimi-cli`를 같은 제품으로 보지 않습니다.

## 수정

- 분할 막대를 끌 때 터미널이 가려지지 않고 크기를 따라갑니다.
- 대화 상자를 열면 제목 표시줄도 어두워집니다. 가림막을 눌러 닫히는 창은 제목 표시줄을 눌러도 닫힙니다.
- 새로 고친 뒤에도 아직 도는 터미널을 잘못 닫지 않습니다.
- 전체 화면 그림이 깜빡이지 않고, 그림 복사가 됩니다.
- 명령줄에 넘기는 댓글은 위치와 본문만 남고 화면 라벨은 붙지 않습니다.
- 입력 메뉴는 지금 상태에 맞춰 열기 또는 닫기를 쓰고, 전환이라고 쓰지 않습니다.
- 여러 파일 Git 변경 목록의 구분선이 보입니다.
- 주석이 있는 OpenCode 설정도 프로젝트 기억에 쓸 수 있습니다.
- 앱 아이콘에 둥근 모서리가 두 겹으로 들어가지 않습니다.
- 세션 종료 카드의 버튼이 제목과 맞고, 경고 아이콘도 첫 줄 글자와 맞습니다.
