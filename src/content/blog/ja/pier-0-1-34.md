Pier 0.1.34（2026-08-30）では、候補版を先に受け取るかを選べます。ウィンドウ移動、コマンドラインからのファイル開き、コミット確認も足しました。

## 候補版を先に受け取れる

設定 → 更新に「候補版を受け取る」を追加しました。初期値はオフです。オンにすると正式版の前に候補版が届き、正式版が出ると自動で置き換わります。オフのままだと正式版だけです。

## パネルを別ウィンドウへ移せる

タブを右クリックします。ウィンドウが2つなら、もう一方へ直接移します。それ以上あるときは、メニューから行き先を選びます。

## コマンドラインでディレクトリとファイルを開く

`pier .` やパスの短縮形は、すでに開いているプロジェクトに戻るか、エディタでファイルを開きます。パスの後ろに `:行` または `:行:列` を付けられます。

## Git 変更ページからコミットを確定

コミットコマンドと未コミットの変更ページは同じ入り口です。確認してからコミットします。今回のチェックは、次回の初期動作を黙って変えません。

## より多くのプロジェクトファイルを識別

Dart、CMake、Python、Go、Maven、Gradle などのプロジェクトファイルを識別し、対応するタスクを用意します。Dart はワークスペースの FVM を優先します。

## その他の改善

- 新しく開いた関連パネルは、今のタブの右に入ります。
- プロジェクト記憶をすでに有効にしたリポジトリでは、リポジトリ内のファイルを変えなくてよく、起動時に説明をコマンドラインへ渡します。
- ウィンドウ見出しにフォルダ名が重複しなくなり、右側には違うブランチか今のファイルだけ出ます。
- コマンドラインに新しい版があるかは、そのインストール元で判断し、古いローカル索引を最新扱いしません。
- 更新対象は Kimi Code だけです。PATH 上の古い Python `kimi-cli` を同じ製品としては扱いません。

## 修正

- 分割バーをドラッグしても、ターミナルは隠れず、サイズについてきます。
- ダイアログを開くとタイトルバーも暗くなります。オーバーレイで閉じられる窓は、タイトルバーをクリックしても閉じられます。
- 更新後、実行中のターミナルを誤って閉じません。
- 全画面の画像が一瞬ちらつかず、コピーもできます。
- コマンドラインへ渡すコメントは位置と本文だけになり、画面上のラベルは付けません。
- 入力欄のメニューは今の状態に合わせて「開く」または「閉じる」と出し、「切り替え」とは書きません。
- 複数ファイルの Git 変更リストで区切り線が見えます。
- コメント付きの OpenCode 設定でも、プロジェクト記憶へ書けます。
- アプリアイコンが二重の角丸になりません。
- セッション終了カードのボタンが見出しと揃い、警告アイコンも先頭行の文字と揃います。

変更の全体は [CHANGELOG](https://github.com/runloom/pier/blob/main/CHANGELOG.md) を参照してください。
