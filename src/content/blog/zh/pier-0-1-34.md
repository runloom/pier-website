Pier 0.1.34（2026-08-30）让你可以选择提前收到候选版本，并补上窗口、命令行打开和提交确认这些日常操作。

## 可以提前收候选版本

设置 → 更新里新增「接收候选版本」，默认关闭。打开后，会在正式版之前收到候选版本；正式版发布后自动换成正式版。不打开则只收正式版。

## 面板可以移到另一个窗口

在标签上右键：只有两个窗口时，直接移到另一个；窗口更多时，从菜单里选目标。

## 用命令行打开目录和文件

`pier .` 或路径简写会跳到已经打开的项目，或在编辑器里打开文件。路径后面可以写 `:行` 或 `:行:列`。

## 在 Git 变更页确认提交

提交命令和未提交变更页走同一个入口，弹出确认后再提交。这次勾选的选项，不会悄悄改掉你下次的默认行为。

## 更多工程文件能识别

能识别 Dart、CMake、Python、Go、Maven、Gradle 等工程文件，并提供对应任务。Dart 项目会优先用工作区里的 FVM。

## 其他改进

- 新开的相关面板会出现在当前标签右侧。
- 已经开启项目记忆的仓库，不必再改仓库里的文件；启动时会把说明交给命令行。
- 窗口标题不再重复文件夹名；右侧只显示不一样的分支或当前文件。
- 命令行是否有新版本，按对应安装源判断，不再把本机过期索引当成最新。
- 只更新 Kimi Code，不会把 PATH 上旧的 Python `kimi-cli` 当成同一个产品。

## 修复

- 拖动分栏时，终端不再被挡住，会跟着改大小。
- 弹出对话框时，标题栏也会变暗；点遮罩能关的窗口，点标题栏也能关。
- 刷新后不会误关还在跑的终端。
- 全屏看图不再闪一下，复制图片可用。
- 交给命令行的评论只保留位置和正文，不再夹带界面标签。
- 输入区菜单按当前状态写「打开」或「关闭」，不再写「切换」。
- 多文件 Git 变更列表的分隔线能看见了。
- 带注释的 OpenCode 配置可以正常写入项目记忆。
- 应用图标不再套两层圆角。
- 会话结束卡片上的按钮与标题对齐；警告图标与首行文字对齐。

完整变更见 [CHANGELOG](https://github.com/runloom/pier/blob/main/CHANGELOG.md)。
