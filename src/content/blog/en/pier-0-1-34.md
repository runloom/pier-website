Pier 0.1.34 (2026-08-30) lets you opt in to release candidates, and fills in everyday moves: another window, opening a path from the command line, and confirming a commit.

## You can opt in to release candidates

Settings → Updates now has “Receive release candidates”, off by default. Turn it on to get candidates before the stable release; when the stable build ships, it replaces the candidate. Leave it off and you only get stable builds.

## Move a panel to another window

Right-click a tab. With two windows, it moves to the other one. With more windows, pick the destination from the menu.

## Open a directory or file from the command line

`pier .` or a path shorthand focuses a project that’s already open, or opens a file in the editor. You can append `:line` or `:line:column`.

## Confirm a commit from the Git changes page

The commit command and the uncommitted-changes page share one entry. A confirm card appears before the commit. What you tick this time does not quietly change the next default.

## More project files are recognized

Dart, CMake, Python, Go, Maven, Gradle, and similar project files are recognized, with matching tasks. Dart prefers the workspace FVM SDK.

## Other improvements

- A related panel opens to the right of the current tab.
- Repositories that already use project memory no longer need a file change in the repo; on launch, the note is handed to the command line.
- Window titles no longer repeat the folder name; the right side only shows a different branch or the active file.
- Whether a CLI has a newer version is judged from its install source, not a stale local index.
- Only Kimi Code is updated. An old Python `kimi-cli` on PATH is not treated as the same product.

## Fixes

- Dragging a split no longer hides the terminal; the terminal resizes with the drag.
- Opening a dialog also dims the title bar. Dialogs that close from the overlay also close from the title bar.
- A refresh no longer closes a terminal that is still running.
- Full-screen image preview no longer flashes, and copying an image works.
- Comments sent to the command line keep only the location and the body, not UI labels.
- Input menus say Open or Close for the current state, not Toggle.
- Separators in a multi-file Git changes list are visible.
- Commented OpenCode config can be written for project memory.
- The app icon no longer gets a double rounded corner.
- Buttons on the session-ended card line up with the title; warning icons line up with the first line of text.
