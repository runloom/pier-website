Pier 0.1.37 (2026-09-03) is now available. This release includes the following changes.

## Added

- **SVG preview in Markdown and review.** Valid SVGs now open as images instead of falling back to a binary-file warning.
- **Diagram previews now use the same official engine.** Markdown, fullscreen, and board views share theme and source formatting; zooming now uses a bitmap to lighten the load.

## Changed

- **The MCP page in Settings is now a cross-agent list.** It’s grouped into Pier-managed, in-project, and user configuration, and shows which agents have access, which don’t yet, and whether each server is a local process or remote. Agents are shown by name, so Grok’s X icon isn’t mistaken for a failure. `pier-memory` opens project memory in repository projects. Pier still doesn’t modify these files or launch these servers.
- **Opening MCP configs from your home directory no longer shows a blank page.** Files outside the workspace now display their real path and contents instead of masquerading as the current project’s `config.yaml`.
- **The New menu now has a stable layout.** The “Manage agents…” item in the footer stays anchored to the popover; command and skill searches use the same ordering.
- **Image previews in the file panel no longer reserve space for a fullscreen title bar.**
- **The mobile web shell now uses a remote-cockpit style.** Conversation, review, and host entries are reorganized around a cockpit information architecture.

## Fixed

- **Memory no longer keeps climbing after the app has been open a long time.** Canvas and block hot updates now tear down the previous runtime environment; usage requests no longer open a hidden window for every challenge.
- **Multiple visible terminals are no longer repeatedly reattached.**
- **Terminal scrollbar clipping now aligns with the system formula.**
- **Tearing a tab off into a new window no longer treats the prewarmed window as an existing target.**
- **The `pier/canvas` module in canvas source code is now resolved by the language service.**
